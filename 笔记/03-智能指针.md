# 03 · 智能指针

> 目标：**从此代码里几乎不再出现裸 `new` / `delete`。** 智能指针是 RAII + 移动语义的完美结晶。

## 1. 裸指针的三大罪

```cpp
int* p = new int(42);
// 1. 忘记 delete → 内存泄漏
// 2. delete 两次 → 未定义行为（double free）
// 3. 指针还指向已释放的内存 → 悬垂指针，解引用就崩
```

智能指针在**析构时自动释放**它管理的对象，同时通过「所有权」语义避免 delete 两次和悬垂。

## 2. unique_ptr —— 独占所有权（默认首选）

**同一时刻只能有一个 `unique_ptr` 拥有这个对象。** 它不能被拷贝，只能被移动。

```cpp
#include <memory>

auto p = std::make_unique<int>(42);   // ✅ 推荐用 make_unique 创建
std::cout << *p << "\n";              // 像普通指针一样解引用

// auto q = p;            // ❌ 编译错误：unique_ptr 不可拷贝（独占所有权）
auto q = std::move(p);   // ✅ 移动：所有权从 p 转移给 q
// p 现在是 nullptr
```

**为什么要 `make_unique`？** 更简洁、异常安全，且避免直接写 `new`。

```cpp
// ❌ 可能泄漏：如果 f 抛异常，new 出来的对象没被 unique_ptr 接管
foo(std::unique_ptr<T>(new T), f());

// ✅ 安全
foo(std::make_unique<T>(), f());
```

**unique_ptr 还能管理数组**（但现代 C++ 里通常用 `std::vector` 更好）：

```cpp
auto arr = std::make_unique<int[]>(10);
```

## 3. shared_ptr —— 共享所有权

多个 `shared_ptr` 可以共同拥有同一个对象，**引用计数**归零时自动释放。

```cpp
auto s1 = std::make_shared<int>(10);
{
    auto s2 = s1;        // 拷贝：引用计数 +1 → 现在是 2
    auto s3 = s1;        // +1 → 3
}                        // s2、s3 析构，计数回到 1
// 这里 s1 还在，对象仍存活
// 等 s1 也析构，计数归 0，对象才被释放
```

获取引用计数：`s1.use_count()`。

**注意**：`shared_ptr` 有额外开销（引用计数是原子操作 + 控制块），**默认先用 `unique_ptr`，确实需要共享时才换 `shared_ptr`。**

## 4. weak_ptr —— 打破循环引用

这是 `shared_ptr` 最经典的坑。两个对象互相持有对方的 `shared_ptr`，引用计数永远到不了 0：

```cpp
struct Node {
    std::shared_ptr<Node> next;
    ~Node() { std::cout << "Node 析构\n"; }
};

{
    auto a = std::make_shared<Node>();
    auto b = std::make_shared<Node>();
    a->next = b;   // b 引用计数 2
    b->next = a;   // a 引用计数 2
}   // ❌ 离开作用域：a、b 的引用计数只从 2 降到 1，永远不为 0 → 泄漏！
    // 你永远不会看到 "Node 析构"
```

**解法：一方用 `weak_ptr`，它不增加引用计数。**

```cpp
struct Node {
    std::shared_ptr<Node> next;   // 强引用
    std::weak_ptr<Node>   prev;   // 弱引用：不占计数，打破循环
};
```

`weak_ptr` 不能直接解引用，要先 `lock()` 升级成 `shared_ptr`（若对象已死则返回空）：

```cpp
std::weak_ptr<int> w = s1;
if (auto sp = w.lock()) {   // 升级成功才使用
    std::cout << *sp << "\n";
}
```

**用途**：缓存、观察者、避免循环引用。判断「对象还活着吗」用 `w.expired()`。

## 5. 自定义删除器（了解）

默认用 `delete` 释放，但有些资源需要特殊释放（比如 C 库返回的指针、文件句柄）：

```cpp
std::unique_ptr<FILE, decltype(&fclose)> f(fopen("a.txt", "r"), &fclose);
// f 析构时自动调用 fclose，而不是 delete
```

## 6. 怎么选（速查表）

| 需求 | 用 |
|---|---|
| 一个对象只有一个拥有者 | `unique_ptr` |
| 多个拥有者共享，生命周期不确定 | `shared_ptr` |
| 观察但不拥有，需要打破循环 | `weak_ptr` |
| 数组 | `std::vector`（而非智能指针数组） |
| 不需要所有权的观察/遍历 | 裸指针 `T*` 或引用（不 delete 即可） |

## 7. 两条纪律

1. **创建用 `make_unique` / `make_shared`**，不要在 `new` 和智能指针之间夹可能抛异常的操作；
2. **所有权和访问分离**：需要「拥有」才用智能指针；只是「看一眼」就用裸指针/引用，别乱用 `shared_ptr` 到处传。
