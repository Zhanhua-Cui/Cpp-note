# 02 · 移动语义与右值引用

> 本阶段最难的一环。它回答一个问题：**拷贝很贵的时候，能不能直接把资源「搬」过来，而不是复制一份？**

## 1. 问题：拷贝为什么让人肉疼

```cpp
std::vector<std::string> make_names() {
    std::vector<std::string> v;
    v.push_back("a very long string ...");   // 塞进大量数据
    return v;
}

int main() {
    std::vector<std::string> x = make_names();
    // C++98：这里要把整个 vector 的内容「复制」一份给 x，然后销毁临时对象
    // → 大量无意义的拷贝，慢。
}
```

理想做法：既然那个临时 vector 马上就死了，**直接把它的内存「抢」过来给 x** 不就行了？这就是移动语义。

## 2. 值类别：左值 vs 右值

| | 左值 (lvalue) | 右值 (rvalue) |
|---|---|---|
| 直觉 | 有名字、有地址、能持久存在 | 临时的、用完即弃、即将销毁 |
| 例子 | 变量 `x`、`*p`、`arr[0]` | 字面量 `42`、表达式 `a+b`、`std::move(x)` |
| 能否取地址 | `&x` 可以 | 通常不行 |

一个简单判断：**能对它写 `&变量` 取到地址的，就是左值；否则是右值。**

## 3. 右值引用 `&&`

```cpp
int a = 10;
int&  lref = a;      // 左值引用：绑定左值
// int&& rref = a;   // ❌ 右值引用不能直接绑左值
int&& rref = 10;     // ✅ 右值引用：绑定右值（临时值）
int&& r2 = a + 1;    // ✅ a+1 是临时值，右值
```

右值引用之所以有用，是因为：**一个右值马上就要销毁了，我们可以安全地「偷」它的资源。**

## 4. 移动构造 + 移动赋值

```cpp
class Buffer {
    char* data_;
    size_t size_;
public:
    explicit Buffer(size_t n) : size_(n) {
        data_ = new char[n];
        std::cout << "构造 " << n << " 字节\n";
    }

    // 拷贝构造：老老实实复制一份（深拷贝）
    Buffer(const Buffer& other) : size_(other.size_) {
        data_ = new char[size_];
        std::copy(other.data_, other.data_ + size_, data_);
        std::cout << "拷贝构造（深拷贝）\n";
    }

    // 移动构造：直接把对方资源「偷」过来
    Buffer(Buffer&& other) noexcept
        : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr;   // 关键！把对方掏空，防止它析构时 double delete
        other.size_ = 0;
        std::cout << "移动构造（窃取资源，O(1)）\n";
    }

    ~Buffer() { delete[] data_; }
};

Buffer make_buffer() {
    Buffer b(1024);
    return b;   // 返回时触发移动（而非拷贝）
}
```

**移动构造的三个要点：**

1. 参数是 `&&`（右值引用）；
2. 直接接管对方的指针（O(1)，不分配不复制）；
3. **必须把对方指针置空**，否则对方析构时会 `delete` 你已经偷走的内存 → double delete。

## 5. std::move

`std::move` 本身**不移动任何东西**。它只是把一个值**强制转成右值引用**，从而让编译器选择移动语义。

```cpp
Buffer a(100);
Buffer b = a;             // 拷贝：a 还要继续用，所以必须复制
Buffer c = std::move(a);  // 移动：你承诺「a 我不再用了」，资源被搬空
// 此后 a 处于「有效但未指定」状态：能析构、能重新赋值，但内容未知
```

**两条铁律：**

1. `std::move` 不是「删除」也不「搬东西」，只是类型转换；
2. 对**即将销毁的对象**才用 `std::move`，普通变量别乱 move，否则自己后面用它就出 bug。

## 6. 移动后对象的状态

被移动走的对象必须是「**有效但未指定**」状态：

- ✅ 可以安全析构；
- ✅ 可以重新赋值 / 复用（`a = Buffer(10);`）；
- ❌ 不要假设它原来的内容还在。

这就是为什么移动构造里要把 `other.data_` 置 `nullptr`——保证 `delete[] nullptr` 是安全的。

## 7. 移动构造要加 noexcept

把移动构造声明为 `noexcept` 很重要，尤其对 `std::vector`：

```cpp
Buffer(Buffer&& other) noexcept { ... }
```

原因：`vector` 扩容时要搬移元素，如果元素的移动构造声明了 `noexcept`，`vector` 就用移动；否则为了异常安全，它退化成**拷贝**，白白损失性能。

## 8. 完美转发（进阶，了解即可）

`std::forward` 用于模板里「把参数原样转发出去，保留它是左值还是右值」：

```cpp
template <typename T>
void relay(T&& arg) {
    target(std::forward<T>(arg));   // arg 是左值就按左值转发，右值就按右值转发
}
```

这里 `T&&` 不是普通右值引用，而是**万能引用（转发引用）**。这个点放到模板进阶再深究，现在知道 `std::forward` 的用途即可。
